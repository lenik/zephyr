# 源文件长度；提取到包子目录

### 长文件争夺所有权

非常长的源文件难以审查、测试和维护。Zephyr 更喜欢内聚的模块——通常位于包子目录下，并有一个简洁的入口文件（与 create/ize 所期望的形状相同）。子目录是可选的：如果辅助功能以其他方式外部化，并且结果可维护，那也是可以的。


### 提升它可以带来的好处

更小的评审差异、更清晰的模块边界、更容易的单元测试，以及繁忙文件上更少的合并冲突。


### 阈值

Lint 会统计非空行（跳过 build/debian/po/…）。大约在 600 行时会出现提示；大约在 1000 行时会出现警告。模板示例模块会被跳过。匹配附近 `.lintignore`（类似 gitignore 样式；可以存在于任意子目录）的路径会被跳过——语言模板默认会忽略 `*.css`。


### 修复是手动的

自己拆分或提取连贯的部分，并更新 meson/install/import 列表。`zfr ize` 不会自动拆分源代码。
