# 소스 파일 길이; 패키지 하위 디렉토리로 추출

### 긴 파일은 소유권을 다툰다

매우 긴 소스 파일은 검토, 테스트 및 관리가 어렵습니다. Zephyr는 응집력 있는 모듈을 선호하며, 종종 얇은 진입점 파일이 있는 패키지 하위 디렉토리 안에 있습니다(생성/생성 예상과 같은 형태). 하위 디렉토리는 선택 사항입니다: 만약 헬퍼를 다른 방식으로 외부화하고 결과가 유지 관리 가능하다면, 그것도 괜찮습니다.


### 그것을 향상시키면 얻을 수 있는 것

더 작은 리뷰 차이, 더 명확한 모듈 경계, 더 쉬운 단위 테스트, 그리고 바쁜 파일에서의 적은 병합 충돌.


### 임계값

Lint는 비어 있지 않은 라인 수를 계산합니다(빌드/build/debian/po/... 등은 건너뜁니다). 약 600라인쯤에 노트가 나타나고, 약 1000라인쯤에 경고가 나타납니다. 템플릿 예제 모듈은 건너뜁니다. 근처 `.lintignore`와 일치하는 경로(gitignore 스타일; 모든 하위 디렉토리에 있을 수 있음)는 건너뜁니다 — 언어 템플릿은 기본적으로 `*.css`를 무시하도록 제공됩니다.


### 수정은 수동입니다

응집된 섹션을 분리하거나 추출하고 meson/install/import 목록을 직접 업데이트하세요. `zfr ize`는 소스를 자동으로 분리하지 않습니다.
