# ソースファイルの長さ; パッケージのサブディレクトリに抽出

### 長いファイルは所有権を争う

非常に長いソースファイルは、レビュー、テスト、管理が困難です。Zephyrは、結合度の高いモジュールを好みます — 多くの場合、パッケージのサブディレクトリ内にあり、薄いエントリーポイントファイルがあります（create/ize が期待するのと同じ形です）。サブディレクトリは必須ではありません：もしヘルパーが他の方法で外部化されていて、その結果が保守可能であれば、それで問題ありません。


### それを改善することで得られるもの

レビューの差分が小さくなり、モジュールの境界が明確になり、ユニットテストが簡単になり、変更が多いファイルでのマージコンフリクトが減ります。


### 閾値

Lintは空でない行をカウントします（build/debian/po/…はスキップ）。約600行あたりで注意が表示され、約1000行で警告が表示されます。テンプレート例のモジュールはスキップされます。近くの `.lintignore` に一致するパス（gitignoreスタイル；任意のサブディレクトリに配置可能）はスキップされます — 言語テンプレートにはデフォルトで `*.css` が無視されるようになっています。


### 修正は手動です

結合したセクションを分割または抽出し、meson/install/import リストを自分で更新してください。`zfr ize` はソースを自動で分割しません。
