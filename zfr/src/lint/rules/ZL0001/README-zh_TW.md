# 原始檔案長度；提取到套件子目錄

### 長文件爭奪所有權

非常長的源文件很難進行審查、測試和管理。Zephyr 更偏好結構完整的模組——通常位於包子目錄下，並帶有一個簡單的入口文件（與 create/ize 所期望的形狀相同）。子目錄是可選的：如果輔助文件以其他方式外部化且結果可維護，那也是可以的。


### 提升它能帶給你的好處

較小的審查差異、更清晰的模組邊界、更容易的單元測試，以及在繁忙檔案上更少的合併衝突。


### 閾值

Lint 計算非空行（跳過 build/debian/po/…）。大約在 600 行左右會出現提示；大約在 1000 行左右會出現警告。範本示例模塊被跳過。匹配附近 `.lintignore`（類似 gitignore；可位於任何子目錄）的路徑會被跳過——語言範本默認忽略 `*.css`。


### 修復是手動的

自行拆分或提取連貫的部分，並更新 meson/install/import 列表。`zfr ize` 不會自動拆分來源。
